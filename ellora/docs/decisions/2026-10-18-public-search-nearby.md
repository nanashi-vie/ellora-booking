Missing pins use a clearly named general/local-area list; they are never presented as measured nearby results. Distance is approximate straight-line kilometers, not road distance or travel time.

## Settled public API contract
Extend `GET /api/customer/salons`; keep the existing `ApiResponse<PageResponse<SalonSummaryResponse>>` envelope and defaults `page=0`, `size=12` (retain existing page/size sanitization, maximum size 50).

| Parameter | Behavior |
| --- | --- |
| `keyword` | Optional trimmed string, maximum 255 characters. Case-insensitive literal substring of salon name or an active service name. Preserve existing city/district keyword matching for backward compatibility. Service matches use `EXISTS`, avoiding duplicate salon rows. |
| `location` | Optional trimmed string, maximum 255 characters. Case-insensitive literal substring of approved address, district or city. Combined with other filters using AND. No geocoder/autocomplete request. |
| `date` | Optional ISO `YYYY-MM-DD`, Vietnam local date; today through one year ahead. Past or out-of-range dates return 400. |
| `time` | Optional `HH:mm`; requires `date`. Exact minute precision; malformed/non-minute values return 400. Combined Vietnam datetime must be at least one hour after the current instant, including across midnight. |
| `latitude`, `longitude` | Optional complete finite pair in [-90,90] and [-180,180]. One missing coordinate or an invalid value returns 400. Real zero coordinates are valid. |
| `radiusKm` | Optional finite number greater than 0 and at most 100. Requires the coordinate pair. Keep only approved valid pins within the inclusive radius. Backend has no implicit radius; frontend nearby requests explicitly use 5 km initially. |
| `sort` | `newest` (default), `rating`, or `distance`; unknown values return 400. `distance` requires coordinates and excludes salons lacking a valid approved pin. |

- All results require `SalonStatus.ACTIVE`. Text filters, opening filters and radius are evaluated before pagination. Escape LIKE wildcards in user text and use bound parameters.
- A date/time filter means **open at that time**, never **appointment available**. A date-only filter means an open interval exists on that date; for today, closing time must be after the earliest selectable minute (current Vietnam time plus one hour, rounded up). If that cutoff reaches tomorrow, today has no matching interval. A future date-only filter requires a valid positive opening interval.
- With a time, use the half-open interval `openTime <= time < closeTime`. Exceptional closure dates override weekly hours. Missing weekly rows use the existing effective defaults: Monday–Saturday 09:00–18:00, Sunday closed. Explicit closed/malformed saved intervals do not match. These checks do not consider service duration, employee shifts or booking conflicts. Booking creation retains its authoritative full validation and lock.
- Compute Haversine/central-angle distance from approved finite, in-range salon pins in the database; clamp floating-point trig input. Filter/count/order in SQL or JPA criteria **before** applying pagination. Stable order: newest id DESC; rating average DESC, review count DESC, id DESC; distance ASC, id DESC. Avoid fetching all salons into Java or ranking only one frontend page.
- Summary DTO adds approved `district`, `latitude`, `longitude`, and nullable `distanceKm`. No center means `distanceKm=null`. Missing/invalid stored pin becomes a null pair and null distance. Ordinary newest/rating searches retain missing-pin salons unless a radius is requested; distance sort/radius excludes them. Pending owner proposals are never read.

## Frontend request and privacy behavior
- Add typed optional search filters while preserving existing `search(keyword,page,size)` callers through an optional options argument or overload. Map the new summary fields without invented coordinates/distances. Request IDs/cancellation prevent older filter/page responses from replacing current results.
- Share only keyword, manual location, date, time, sort and radius in route state. Coordinates live in a browser-only, session-memory service. A nearby/distance URL reloaded without a center must explain that a location is needed and offer manual filters; do not send an invalid distance/radius API request or invent a center. Clear stale device center when selecting a manual area.
- Coordinates necessarily travel to the first-party search API as GET query parameters. Do not log them or transfer-cache geolocated responses into SSR HTML. Opt geolocated calls out of Angular transfer cache; no third-party geocoder receives the user's location.
- Change only the SSR document's geolocation policy to permit same-origin usage (`geolocation=(self)`), retaining other restrictions. Browser geolocation requires a secure context and user consent. Use a one-shot request with bounded timeout and error/fallback handling. Keep SSR and test environments from requesting location.
- Search-map pins represent valid approved coordinates from the current result page; disclose that scope. Use canonical OSM tiles, visible attribution and normal browser caching. Popup labels must use text nodes or escaped content. Keep visibility/lazy loading, cleanup, stale-input protection and accessible list navigation.
