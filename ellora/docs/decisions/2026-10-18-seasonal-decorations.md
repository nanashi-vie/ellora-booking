## Product calendar and reusable implementation
- Product season calendar uses the current month in `Asia/Ho_Chi_Minh`: March–May spring, June–August summer, September–November autumn, December–February winter. This is an explicit presentation rule, not measured local weather. October renders autumn. No location request, network weather service, public query-string override or owner-selected season is introduced.
- Add a small shared seasonal service with a pure exported month/date-to-season helper, a testable clock injection token and shared in-memory pause state. Capture one Vietnam month for an application visit; no interval/date polling. Re-evaluate on a fresh app visit. Built-in Angular TransferState can carry the captured server month to the browser to avoid hydration mismatch at month boundaries; browser APIs are not needed to compute it.
- Add one standalone leaf decoration component with explicit scene input (`home-border` or `vip-detail`), reused from Home and VIP SalonDetails. Deterministic fixed particle positions/delays avoid random markup and per-render creation. Injectable fixed season/date is for unit tests and clearly labeled local preview only, never for bypassing production VIP eligibility.
- Prefer small native CSS primitives for yellow/pink petal pieces, recognizable aqua beach waves and orange/white lifebuoy rings, amber leaves and visible snow dots. Preserve meaningful seasonal differences without replacing real salon photos or adding image libraries. Keep all decorative imagery separate from semantic content.
- Effects stay near page edges and the hero/gallery area, leaving headings, inputs, photos and booking buttons readable. Home border remains thin and contained around its public presentation. The leaf must not change existing page width/scroll/footer/sticky behavior. Account for mobile `.page-surface` transforms/paint containment before using `position:fixed`; prefer bounded page-local layers or safe placement rather than assuming a descendant fixed layer is viewport-fixed. No unrelated layout rewrite.

## Motion, accessibility and performance
- Decorative layers have `aria-hidden="true"`, no focusable descendants, `pointer-events:none`, no tooltip or click target. Their clipped bounds create no horizontal overflow and their z-index cannot cover Header, menus, calendar, map controls or booking CTA content.
- Provide a real native button outside the aria-hidden layer to turn effects off/on, with a clear Vietnamese label and pressed state. Shared memory-only pause carries Home→VIP navigation; no localStorage or preferences endpoint. Keep the button in a predictable accessible location with existing secondary-button styling, avoiding floating overlap with current controls.
- Respect `prefers-reduced-motion` in CSS and runtime behavior: reduced motion keeps a quiet static seasonal frame/scene and no falling/drifting animation. Do not override the OS preference when the toggle is pressed. Browser media-query listeners attach after render behind platform guards and are removed on teardown. SSR creates no matchMedia/DOM/timer work.
- Animate only transform/opacity with slow, staggered movement; avoid flashing, large blur/filters, layout-property animations, canvas, JS animation loops or pointer/scroll listeners. Use a small fixed budget (at most roughly 12 moving pieces on desktop and 6 on narrow screens, plus a few wave/frame layers). Pause removes animation work; route changes clean up listeners and leaf resources. No numerical performance improvement claim without measurement.
