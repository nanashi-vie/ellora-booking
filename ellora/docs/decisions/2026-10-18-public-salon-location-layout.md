# Public salon location and booking card

## Design read and audit
- Targeted evolution of the public salon detail page for customers, preserving Ellora's white/rose brand, existing serif headings, routes, gallery, services and booking flow. Apply the local `design-taste-frontend` skill to these two public-facing sections. Design variance 4, motion intensity 1, visual density 4: compact information with clear actions, without a site-wide redesign, new fonts/theme system or design-library migration.
- The main location section currently contains a blank decorative map and hardcoded `SoHo, New York`. The booking card contains an unrelated SPA address and English directions label. These are incorrect content, rather than business data.
- Retain the established Angular/Tailwind/native CSS system, 12–16px card corners and rose controls with dark readable text. Reuse existing icons. Keep the existing whole-page light theme and accessibility/booking behavior; do not introduce unrelated global styling or motion.

## Implementation plan
- Make public `Salon.coordinates` a nullable complete finite in-range pair, preserving real zero coordinates. Add optional district mapping from the existing salon detail response. Search results without coordinates must remain null; never invent `(0,0)`.
- Main location and sidebar share the same trimmed address/district/city and directions helper. Remove both hardcoded locations. Directions prefer approved coordinates, then the URL-encoded real address; omit the action when both are absent. Keep one Vietnamese directions label.
- Restyle only the location section and booking card for a compact, readable white/rose presentation. Keep the booking CTA, selected-service query parameters, working hours and sidebar behavior functional; preserve all other sections.
- For an approved pin, show a read-only Leaflet/OpenStreetMap map, using the existing browser-only lazy loader. Defer map loading until visible; retain visible attribution, fixed space, retry/error cleanup and safe route changes. No selection, dragging, geolocation, search API or new dependency. If no pin exists, show the actual address cleanly without a fake map marker or decorative blank map.
- Use only public approved salon fields. Pending owner proposals remain private to moderation; no backend, migration or database edits are required. Preserve all existing local changes and host settings. No push/deployment is requested.

## Follow-up search discussion (proposal only)
- The current header location/time controls are not connected to real filtering. Search supports a keyword matching salon name/city/district. Home and detail nearby lists currently reuse general search results, and search-map pin positions do not represent actual salon coordinates. No location permission was requested and no search/geolocation behavior was changed in this task.
- Recommend a location field with manual city/district and an explicit opt-in device-location action. Use approved salon coordinates, approximate straight-line distance, a selectable radius and server-side distance sorting before pagination; omit invented distances for missing pins. Home nearby uses the customer's chosen position, while detail nearby can use the current salon's approved position.
- Keep time optional (Any time). First support open-at-time filtering with weekly hours and exceptional closure dates, respecting the existing today-plus-one-hour booking rule. Actual slot availability needs service duration, staff/capacity and conflict checks across the whole interval, plus revalidation on booking. There is currently no dedicated slot-availability API.
- Browser location requires user permission and a secure context. The current SSR document geolocation policy blocks it; a future implementation should allow same-origin geolocation on the document and check deployed response headers. No security headers were relaxed here. References: https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition and https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy/geolocation.
